SaMD · SiMD Penetration Testing — Worked Example

의료기기 소프트웨어 보안 평가 계획서 — 상세 실무 가이드

초보 평가자도 순서대로 따라 할 수 있도록, 하나의 대표 대상(PACS·영상 뷰어 SaMD)을 기준으로 전체 침투 테스트 절차를 각 툴의 실행 예와 예상 결과까지 포함해 기술합니다. SiMD(내장형) 적용 차이는 각 절에서 함께 안내합니다.

버전 1.0대상 예시 PACS·영상 뷰어 (SaMD) 분류 SaMD / SiMD용도 승인된 격리 평가 전용

SaMD / SiMD 소개

SaMD(Software as a Medical Device)는 하드웨어와 독립적으로 의료 목적을 수행하는 소프트웨어입니다(예: AI 진단 앱, 분석 클라우드, PACS 영상 뷰어). SiMD(Software in a Medical Device)는 물리 의료기기의 일부로 동작하는 내장 소프트웨어입니다(예: 인퓨전 펌프 펌웨어, 환자 모니터, 이식형 기기).

둘은 "의료 소프트웨어"라는 점은 같지만 공격 표면과 안전 영향이 다르므로 테스트 전략도 달라집니다.

관점SaMD (독립형)SiMD (내장형)
주 공격 표면웹/API, 인증·세션, 클라우드 설정, 모바일 저장소, 서버 로직펌웨어, 디버그 포트(UART/JTAG), 무선 프로토콜, 부트체인, 센서/액추에이터 경로
핵심 단계정찰 → 웹/API → 인증·암호 → 프로토콜펌웨어 추출/분석 → 무선·BLE → 프로토콜 퍼징 → 물리 인터페이스
안전 영향데이터 무결성·가용성 (오진, PHI 유출)직접적 환자 위해 (용량 변조, 정지) — 격리 벤치 필수
대표 표준FDA Premarket, OWASP ASVS/MASVS, HIPAAIEC 62304, AAMI TIR57, IEC 81001-5-1, ISO 14971
이 가이드의 범위본문 5장은 SaMD(PACS 뷰어) 기준으로 상세히 전개하고, 각 절 끝에 “SiMD 적용” 메모로 내장형 차이(펌웨어·무선·하드웨어)를 안내합니다.

4

테스트 환경 네트워크 구성

평가 전 격리된 테스트베드를 먼저 구축합니다. 핵심은 임상·운영망과의 완전 분리, 외부는 통제 게이트웨이로만, 전 구간 트래픽 캡처입니다.

방화벽 / 라우터 LAB 내부 라우팅 (VLAN 버스) 격리 경계 · 통제 게이트웨이(선택) TAP트래픽 캡처 지점 (TAP/SPAN)

구축 체크리스트

  • 세그먼트 분리 — 공격자(VLAN10)·타깃(VLAN20)·시뮬레이터(VLAN30)·관리/캡처(VLAN40)를 VLAN으로 분리하고 방화벽에서 허용 규칙만 개방.
  • 외부 차단 — 기본 아웃바운드 차단. 업데이트/클라우드 연동 테스트가 필요하면 통제 프록시로만 허용하고 전수 로깅.
  • 가시성 — 관리 VLAN에 TAP/SPAN으로 전 구간 pcap 수집 (`tcpdump`/`tshark`).
  • 합성 데이터 — 시뮬레이터(Orthanc 등)에 합성 DICOM/환자 레코드만 적재.
  • 복원성 — 타깃 VM 스냅샷, 구성 문서화, 킬스위치(전원/링크 차단) 준비.
SiMD 적용내장형은 위 구성에 Faraday 차폐 공간(BLE/RF), 하드웨어 벤치(UART·JTAG·플래시), 모의 부하(dummy load)를 추가합니다. 자세한 분기는 테스트베드 섹션 참조.
5

테스트 절차 (단계별 · 툴 예시)

아래 7단계를 순서대로 진행합니다. 각 단계는 목적 → 대표 툴(실행 예 + 예상 결과 + 초보자 메모) → SiMD 적용 순입니다. 모든 명령은 격리 테스트베드의 가상 대상(10.10.0.20)을 예로 듭니다.

5.1 정찰 · OSINT — 대상의 윤곽 파악

목적: 대상의 호스트·서비스·기술 스택·외부 노출을 비침투적으로 파악해 이후 단계 범위를 정합니다.

nmap살아있는 호스트 탐색상세 →
실행 예
nmap -sn 10.10.0.0/24
예상 결과 (발췌)
Nmap scan report for pacs.lab.local (10.10.0.20)
Host is up (0.00032s latency).
Nmap scan report for sim.lab.local (10.10.0.30)
Host is up (0.00041s latency).
Nmap done: 256 IP addresses (2 hosts up)

초보자 메모: -sn은 포트를 열지 않고 "누가 켜져 있는지"만 봅니다. 대상 IP(10.10.0.20)가 살아있음을 확인했으니 다음은 이 호스트를 자세히 봅니다.

whatweb웹 기술 스택 식별상세 →
실행 예
whatweb -a 3 https://pacs.lab.local
예상 결과 (발췌)
https://pacs.lab.local [200 OK]
Country: RESERVED, HTTPServer: nginx/1.24.0,
X-Powered-By: Express, JQuery[3.5.1], HTML5,
Title: PACS Web Viewer

초보자 메모: 서버(nginx)·프레임워크(Express)·라이브러리 버전(jQuery 3.5.1)이 보입니다. 구버전 라이브러리는 5.4 웹 단계에서 알려진 취약점과 대조합니다.

wafw00f웹 방화벽 탐지상세 →
실행 예
wafw00f https://pacs.lab.local
예상 결과 (발췌)
[*] Checking https://pacs.lab.local
[+] No WAF detected by the generic detection

초보자 메모: WAF가 없으면 이후 웹 테스트가 차단 없이 진행됩니다. WAF가 있으면 탐지·차단을 고려해 속도·페이로드를 조정합니다.

SiMD 적용내장형은 네트워크 정찰 대신 제조사 문서·펌웨어 다운로드·FCC ID·공개 CVE 수집이 중심입니다. 무선 기기는 kismet으로 주변 신호를 식별합니다.

5.2 탐지 · 스캐닝 — 서비스와 알려진 취약점

목적: 열린 포트·서비스 버전을 정밀 식별하고, 알려진 취약점·설정 오류의 1차 목록을 만듭니다.

nmap포트·버전·스크립트 스캔상세 →
실행 예
nmap -sV -sC -p- --open 10.10.0.20
예상 결과 (발췌)
PORT      STATE SERVICE    VERSION
22/tcp    open  ssh        OpenSSH 9.6
104/tcp   open  dicom?
443/tcp   open  ssl/http   nginx 1.24.0
8042/tcp  open  http       Orthanc DICOM server
11112/tcp open  dicom?

초보자 메모: 104/11112(DICOM)·8042(Orthanc 관리) 포트가 보입니다 → 5.3에서 DICOM 프로토콜을, 8042 관리 UI는 5.4에서 점검합니다. -p-는 전체 65535 포트를 봅니다(느릴 수 있음).

nuclei템플릿 기반 취약점 스캔상세 →
실행 예
nuclei -u https://pacs.lab.local -severity medium,high,critical
예상 결과 (발췌)
[tls-version] [ssl] [info] pacs.lab.local:443
[missing-sri] [http] [info] https://pacs.lab.local
[exposed-swagger] [http] [medium] https://pacs.lab.local/api-docs
[orthanc-default-login] [http] [high] 10.10.0.20:8042

초보자 메모: 각 줄이 하나의 발견 후보입니다. [high] Orthanc 기본 로그인, 노출된 API 문서(Swagger)는 우선 검증 대상입니다. 이 목록을 그대로 믿지 말고 5.4~5.6에서 수동 확인합니다.

5.3 프로토콜 · 트래픽 분석 — DICOM 보안

목적: 의료 프로토콜(DICOM)의 인증 부재·평문 전송·정보 노출을 확인합니다. PACS의 핵심 위험 영역입니다.

dcmtk · echoscuDICOM 연결·인증 확인상세 →
실행 예
echoscu -v 10.10.0.20 104
예상 결과 (발췌)
I: Requesting Association
I: Association Accepted (Max Send PDV: 16372)
I: Sending Echo Request (MsgID 1)
I: Received Echo Response (Success)
I: Releasing Association

초보자 메모: "Association Accepted"가 자격증명 없이 떴다면, 누구나 이 DICOM 노드와 통신할 수 있다는 뜻입니다(인증 부재). 이는 보고 대상 발견입니다.

dcmtk · findscu비인증 환자정보 조회 점검상세 →
실행 예 (합성 데이터 대상)
findscu -v -S -k QueryRetrieveLevel=STUDY -k PatientName="*" 10.10.0.20 104
예상 결과 (발췌 · 가상 데이터)
I: Association Accepted
I: Find Response: 1 (Pending)
I:   (0010,0010) PN [TEST^SYNTHETIC-001]   # PatientName
I:   (0008,0050) SH [ACC000123]            # AccessionNumber
I: Final Find Response: Success

초보자 메모: 인증 없이 환자명(PatientName) 등 레코드가 반환되면 정보 노출입니다. 테스트는 반드시 합성 데이터에서만 하며, 실제 PHI가 반환되는 운영 시스템에서는 수행하지 않습니다.

tshark평문 전송 여부 관찰상세 →
실행 예
tshark -i eth0 -f "tcp port 104" -Y dicom -T fields -e dicom.command
예상 결과 (발췌)
1   (A-ASSOCIATE-RQ)
1   (A-ASSOCIATE-AC)
0x0030  C-ECHO-RQ
0x8030  C-ECHO-RSP

초보자 메모: DICOM 내용이 평문으로 보이면 전송 암호화(TLS) 미적용입니다. 네트워크를 가로채는 공격자가 영상·환자정보를 볼 수 있다는 의미입니다.

주의 — C-STORE 쓰기 테스트임의 객체 전송(C-STORE) 허용 여부 점검은 저장소를 변경할 수 있으므로 반드시 격리 시뮬레이터(Orthanc 등)에서, 스냅샷 후 수행합니다.

5.4 웹 · API 테스트

목적: 웹 포털·관리 UI·REST API의 인증·인가·입력검증 결함을 찾습니다.

nikto웹 서버 설정 점검상세 →
실행 예
nikto -h https://pacs.lab.local
예상 결과 (발췌)
+ Server: nginx/1.24.0
+ The X-Content-Type-Options header is not set.
+ Missing: Strict-Transport-Security header.
+ /api-docs/: Swagger UI found (API documentation exposed).

초보자 메모: 보안 헤더 누락·노출된 문서가 보입니다. 각 항목을 "왜 위험한가(영향)"와 함께 기록합니다.

ffuf숨은 경로 탐색상세 →
실행 예
ffuf -u https://pacs.lab.local/FUZZ -w /usr/share/wordlists/dirb/common.txt -mc 200,301,403
예상 결과 (발췌)
admin                   [Status: 200]
api                     [Status: 301]
backup                  [Status: 403]
api-docs                [Status: 200]

초보자 메모: /admin·/backup 같은 경로가 노출되면 다음에 접근 통제를 점검합니다. 403도 "존재하지만 차단"이라 의미가 있습니다.

Burp Suite인증·인가·세션 (수동)상세 →
절차 (수동)
  1. 브라우저 프록시를 Burp(127.0.0.1:8080)로 지정, Burp CA 신뢰 등록
  2. 로그인 후 한 요청을 Repeater로 보냄: GET /api/studies?patientId=1001
  3. patientId를 다른 값(1002)으로 바꿔 재전송 → 응답 확인
예상 결과 — 취약 시 (IDOR)
HTTP/1.1 200 OK
{ "patientId":1002, "name":"TEST^SYNTH-002",
  "studies":[{"accession":"ACC000890"}] }

초보자 메모: 내 계정으로 다른 환자(1002) 데이터가 조회되면 접근통제 결함(IDOR)입니다. PHI가 걸린 SaMD에서 가장 흔하고 위험한 유형입니다.

sqlmapSQL 인젝션 자동 점검상세 →
실행 예 (합성 DB 대상)
sqlmap -u "https://pacs.lab.local/api/studies?patientId=1" --batch --level=2
예상 결과 (발췌)
[INFO] testing 'patientId' parameter
[INFO] parameter 'patientId' appears to be injectable
[INFO] the back-end DBMS is PostgreSQL

초보자 메모: "injectable"이 뜨면 인젝션 가능성이 있습니다. 데이터 추출(--dump)은 승인된 범위·합성 DB에서만, 영향 입증에 필요한 최소한으로 수행합니다.

5.5 인증 · 암호 (전송 보안)

목적: PHI 전송 구간의 TLS 강도·인증서·약한 자격증명을 점검합니다.

sslscanTLS 구성 점검상세 →
실행 예
sslscan pacs.lab.local:443
예상 결과 (발췌)
  TLSv1.0   enabled   <-- 약한 프로토콜
  TLSv1.3   enabled
  Accepted  TLSv1.0  112 bits  TLS_RSA_WITH_3DES... <-- 약한 암호군
  Certificate: expires 2026-11-01

초보자 메모: TLS 1.0/약한 암호군이 켜져 있으면 PHI 전송이 약하게 보호됩니다. HIPAA·FDA 전송 보안 요구와 연결해 보고합니다.

초보자 메모: 기본 계정(admin/orthanc 등)이 남아 있으면 즉시 보고합니다. 계정 잠금 정책이 없는지도 함께 확인합니다. 무차별 시도는 승인·속도 제한을 지켜 수행합니다.

5.6 취약점 검증 (통제된 PoC)

목적: 앞에서 식별한 후보를 실제 영향으로 입증합니다. 가용성·안전에 영향을 줄 수 있으므로 격리 환경에서, 최소 침습으로 수행합니다.

  • IDOR(5.4): 서로 다른 테스트 계정으로 교차 조회가 되는 화면/응답을 캡처해 재현 절차와 함께 기록.
  • DICOM 비인증(5.3): echoscu/findscu 성공 로그 + 합성 레코드 반환 캡처로 정보 노출 입증.
  • 알려진 CVE: 식별된 구성요소 버전을 공개 취약점 DB와 대조. 공개 익스플로잇은 격리 복제본에서만 통제 실행(metasploit), 영향(예: 서비스 중단) 확인 후 즉시 스냅샷 복원.
안전 원칙DoS·충돌을 유발할 수 있는 검증은 운영과 분리된 복제본에서만, 안전 담당자 승인 하에, 복원 계획을 준비한 뒤 수행합니다. SiMD의 액추에이터·용량 제어 경로는 모의 부하로 대체합니다.

  • 발견마다: 제목 · 영향 · 재현 절차 · 증거(명령/출력/스크린샷) · CVSS · AAMI TIR57 안전 위해도 · 권고.
  • SBOM 대조: 구성요소 목록을 알려진 취약점과 대조(가능 시 grype/trivy 추가 설치).
