FDA Premarket Cybersecurity Submission

FDA 사이버보안 제출 가이드 — 요소별 완성법

FDA 시판 전 사이버보안 제출(FD&C Act §524B · 2023 가이드 "Cybersecurity in Medical Devices")의 요소를 설명하고, MedPen이 산출하는 부분과 제출 등급으로 채우는 방법을 안내합니다. 침투 테스트 결과서는 이 패키지의 한 구성요소입니다.

⚠️ 중요 — 이 도구만으로는 제출물이 완성되지 않습니다 MedPen은 방법론·계획서/결과서 템플릿과 침투 테스트 수행을 돕습니다. 실제 제출물은 대상 기기에 대한 실측 결과와 아래 요소 전체를 설계관리(21 CFR 820 / ISO 13485) 체계 안에서 작성해야 합니다. 이 문서는 기술 안내이며 규제 자문이 아닙니다 — 제출 전 RA 담당·FDA 가이드 원문·필요시 Q-Submission으로 확인하세요.

1

개요 — 무엇이 요구되는가

2023년 제정된 FD&C Act §524B는 "사이버 기기(cyber device)"에 대해 사이버보안 정보 제출을 의무화합니다. FDA 2023 가이드는 제출물에 위협 모델링, 보안 위험 관리, 보안 아키텍처, SBOM, 보안 테스트(침투 테스트 포함), 라벨링, 사후시장 관리 계획을 포함하도록 권고합니다.

핵심은 "보안을 품질 시스템(QMS)과 제품 생명주기에 통합했다"는 것을 문서로 입증하는 것입니다. 침투 테스트 하나로는 부족하며, 설계 단계의 위협 모델·위험 관리와 연결되어야 합니다.

3

요소별 상세 · 완성법

위협 모델링 결과서 3장

FDA 기대: 데이터 흐름·신뢰 경계·진입점·자산 식별, 위협 도출(STRIDE 등), 각 위협의 완화 연결.
완성법: 기기 데이터흐름도(DFD)를 그리고, 진입점별 STRIDE 위협을 표에 채웁니다. 각 위협은 4장 위험 평가·8장 테스트와 ID로 연결.
흔한 미흡: 일반론만 기술하고 기기 특정 데이터 흐름·신뢰 경계가 없음.

보안 위험 평가 결과서 4장

FDA 기대: AAMI TIR57/SW96에 따라 보안 위험을 안전 위험(ISO 14971)과 연계, 통제 후 잔여 위험 수용 판단.
완성법: 위협별 가능성·영향(안전 포함)을 산정하고 통제·잔여위험·수용 여부를 기록. 환자 안전 영향이 큰 항목은 위해도 매트릭스로 우선순위화.
흔한 미흡: 보안 위험을 안전 위험과 분리해 다룸(연계 누락).

보안 아키텍처 뷰 결과서 5장

FDA 기대: 글로벌 시스템 / 다환자 위해 / 업데이트·패치 / 보안 유스케이스의 4대 뷰.
완성법: 각 뷰를 다이어그램 + 설명으로 작성. 특히 "한 기기 침해가 다수 환자에 미치는 경로"와 "서명된 업데이트 검증"을 명확히.
흔한 미흡: 다환자 위해 뷰·업데이트 검증 경로 누락.

SBOM + 취약점 분석 결과서 6장 · syft/trivy

FDA 기대: 기계판독 SBOM(구성요소·버전·지원상태), 알려진 취약점 대조, 미지원/EOL 구성요소 관리.
완성법: syft dir:./app -o cyclonedx-json로 SBOM 생성 → trivy sbom·pip-audit로 CVE 대조 → 각 구성요소의 조치·EOL을 표에 기록.
흔한 미흡: SBOM이 기계판독 포맷(CycloneDX/SPDX)이 아니거나 취약점 대조·EOL 정보 없음.

보안 요구사항 ↔ 검증 결과서 7장

FDA 기대: 보안 요구사항과 그 검증(테스트) 증거의 추적성.
완성법: 요구사항 ID ↔ 출처(표준) ↔ 검증 방법(툴) ↔ 결과 ↔ 증거를 표로 연결. 설계관리 문서와 상호 참조.
흔한 미흡: 테스트는 있으나 요구사항과의 추적 연결이 없음.

침투 테스트 결과서 8장 · 방법론

FDA 기대: 범위·방법·기간·테스터 자격/독립성, 발견별 심각도·재현·증거·수정/재검증.
완성법: MedPen 9단계로 수행하고 발견을 등록부·상세 양식에 기록. 테스터 독립성·자격·공수를 명시(4장 참조).
흔한 미흡: 독립성·자격·기간 미기재, 발견 재현 절차·증거 부족.

라벨링 · 사후시장 관리 결과서 11장

FDA 기대: 사용자용 보안 설명서, 취약점 공개(coordinated disclosure) 정책, 패치·SBOM 유지, 모니터링 계획.
완성법: 취약점 접수 창구·대응 SLA·공개 정책, 업데이트 배포·서명·검증, SBOM 갱신 주기를 문서화.
흔한 미흡: 사후시장 취약점 처리 절차·공개 정책 부재.
4

테스터 독립성 · 자격

FDA는 보안 테스트를 적격한 인력이 수행하기를 기대하며, 많은 리뷰어가 독립성(개발팀과 분리, 또는 제3자)을 중요하게 봅니다.

  • 독립성 수준을 명시: 사내 독립팀 / 제3자 독립 / 개발팀 — 선택 근거 포함.
  • 자격을 기재: 관련 자격(OSCP/GPEN 등)·의료기기 보안 평가 경험.
  • 기간·공수(person-day)와 범위를 명시해 테스트의 충분성을 보임.
결과서에 반영됨결과서 8장 상단에 테스터 자격·독립성·기간·방법론 표가 포함되어 있습니다.
5

작성 워크플로

  1. 설계 단계: 위협 모델 → 보안 위험 평가 → 보안 요구사항 도출 (설계관리 연계).
  2. 구현/통합: SBOM 생성(syft) + 취약점 대조(trivy/pip-audit), 아키텍처 뷰 작성.
  3. 검증: MedPen 9단계 침투 테스트 수행(독립성 확보) → 요구사항↔검증 추적.
  4. 문서화: 빌더 → 결과서 템플릿 생성 → 각 장을 실측 결과로 채움 → DOCX/PDF.
  5. 사후시장: 취약점 공개·패치·SBOM 유지 계획 수립.
  6. 검토: RA 담당 검토 → 필요시 FDA Pre-Submission(Q-Sub).
6

한계 · 면책

  • MedPen은 방법론·템플릿·테스트 보조 도구이며, 그 자체가 FDA 제출물이 아닙니다.
  • 예시 명령·출력·프로파일은 교육용 가상 데이터입니다. 실제 제출은 대상 기기 실측 결과가 필요합니다.
  • 규제 요구는 개정될 수 있습니다. 제출 전 반드시 FDA 가이드 원문과 RA(규제 담당) 검토를 거치세요.
  • 본 문서는 기술 안내이며 법률·규제 자문이 아닙니다.
