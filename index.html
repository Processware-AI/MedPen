02

SaMD vs SiMD 공격 표면

같은 "의료 소프트웨어"라도 공격 표면과 안전 영향이 다릅니다. 방법론 빌더는 이 차이를 반영해 단계를 배분합니다.

관점SaMD · 독립형SiMD · 내장형
정의하드웨어와 독립적으로 의료 목적을 수행하는 소프트웨어 (진단 앱, 분석 클라우드, PACS 뷰어)물리 의료기기의 일부로 동작하는 소프트웨어 (인퓨전 펌프, 모니터, 이식형 펌웨어)
주 공격 표면웹/API, 인증·세션, 클라우드 설정, 모바일 앱 저장소, 서버측 로직펌웨어, 디버그 포트(UART/JTAG), 무선 프로토콜, 부트체인, 센서/액추에이터 경로
핵심 단계정찰 → 웹/API 테스트 → 인증·암호 → 프로토콜펌웨어 추출/분석 → 무선·BLE → 프로토콜 퍼징 → 물리 인터페이스
안전 영향데이터 무결성·가용성(오진, PHI 유출)직접적 환자 위해(용량 변조, 정지)—테스트는 반드시 격리 벤치에서
대표 표준FDA Premarket Cybersecurity, OWASP ASVS/MASVSIEC 62304, AAMI TIR57, IEC 81001-5-1, MITRE Rubric
03

테스트베드 네트워크 구성

SaMD/SiMD 테스트 환경은 격리(isolation)와 현실 재현(fidelity)의 균형이 핵심입니다. 임상·운영망과 완전히 분리하되, 실제 배포 환경을 충분히 재현해야 유효한 결과가 나옵니다. (IEC 80001-1 · IEC 62443 참조)

임상·운영망과 완전 분리 · 외부는 통제 게이트웨이로만 · 전 구간 TAP/SPAN 캡처 (좁은 화면에서는 가로 스크롤)

SaMD 랩 독립형

  • 스테이징/프리프로덕션 환경 복제 (프로덕션 금지)
  • 클라우드 API·업데이트 서버는 통제 프록시로만, 전수 로깅
  • 모바일: 전용 Wi-Fi AP + mitmproxy 투명 프록시, 테스트 CA 신뢰 등록(핀닝 검증)
  • TLS 가시성 확보 후 웹/API·인증·세션 평가

SiMD 랩 내장형

  • BLE/무선은 Faraday 차폐 공간에서 (간섭·오동작 방지)
  • 전용 RF(ISM 등)는 차폐 환경 SDR·안테나, 송신 법적·격리 조건 준수
  • 하드웨어 벤치: UART·JTAG/SWD·플래시·CAN 분리 연결
  • 액추에이터·용량 경로는 모의 부하로 대체, 펌웨어는 QEMU 에뮬
  • ✓완전 분리 — 임상·운영망과 물리/논리 분리, 환자 연결 장비 접속 금지
  • ✓합성 데이터 — 실제 PHI 금지, 캡처 산출물 암호화 보관·계약 종료 시 파기
  • ✓전구간 가시성 — TAP/SPAN pcap + 중앙 로그로 모든 트래픽 기록
  • ✓복원성 — DUT 스냅샷·IaC 구성·킬스위치(전원/링크 차단)
  • ✓안전 전제 — SiMD/이식형 실동작 테스트는 안전 담당자 승인·하드웨어 안전장치 하에서만

툴 카탈로그

05

표준 · 근거

방법론 단계는 아래 규제·프레임워크에 매핑됩니다. 평가 보고서 작성 시 추적성(traceability) 근거로 사용하세요.

FDA 2023

Premarket Cybersecurity Guidance

SBOM, 위협 모델링, 침투 테스트 증거를 시판 전 제출물에 요구. SaMD/SiMD 공통.

IEC 62304

Medical Device Software Lifecycle

소프트웨어 안전 등급(A/B/C)과 생명주기 프로세스. SiMD 펌웨어 평가의 기준선.

AAMI TIR57

Security Risk Management

보안 위험을 안전 위험 관리(ISO 14971)와 연계. 발견 항목의 위해도 산정에 사용.

IEC 81001-5-1

Health Software Security

헬스 소프트웨어의 보안 활동을 생명주기 전반에 규정. 사후시장 포함.

OWASP

ASVS · MASVS · API Top 10

SaMD 웹·API·모바일 검증 체크리스트. 테스트 케이스 도출의 실무 기준.

MITRE

Medical Device Rubric / ATT&CK

위협 모델링과 공격 기법 분류. 절차 각 단계의 기법 매핑에 활용.
